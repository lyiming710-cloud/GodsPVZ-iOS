# R28 植物与僵尸特殊功能专项

本轮游戏 DLL 沿用 R28 `9081408a…f364`，SDK 沿用 `51f72bcd…c2b`，没有新增游戏方法补丁。

已实际完成 20 个方法、3,285 个受控状态的候选原始 CIL 与原版 PC 机器码对照。返回值、状态和调用顺序均无差异。原版调用者没有被替换；Unity API、被调用的游戏方法和对象图中未执行的部分是明确列出的受控契约。该结果不证明这些被调用方法或整个游戏的行为正确。

范围包括技能充能、层数与持续时间、手动索敌入口、治疗、巨噬花吞噬与储存值、特殊伤害系数、元素防具门、梯子放置开始、撑杆跳跃开始/结束、雪兽体力消耗/恢复/清理引用。原版本来为空的 `PC_Chomperviking`、`SkillManager.Function11` 保持空实现。

输入中既有合成边界，也有原版技能等级与序列化默认值。原配置表包含未命名占位条目，它们只算边界数据，不能据此宣称对应植物可玩。各类数量在 `CONTROLLED-RESULTS.json` 中分列；3,285 是场景数，20 才是方法数。

18 个实际改坏字节的 DLL 变体均已被检出。每个变体仍通过原来的冻结类型检查，而且至少一个正常执行用例的返回值或状态发生变化。此证据仅用于说明这套专项比较能识别所列行为错误，不代表所有可能错误均可检出。物理变体保存在本机目录，归档保存了可从固定 DLL 重建的全部字节差分、执行结果和日志。

## 真实 Unity 专项

新增 `scripts/actions/GodsPVZSpecialAuditR28.cs`，一次执行 18 个受控实例场景。它在 MainMenu 实际启动后，克隆原始植物/僵尸预制体，明确设置测试状态并调用实际游戏方法；技能 UI、Animator、治疗飘字等被调用实现也实际执行，没有挂钩或替换。

这些实例处于隔离的非活动根对象下；植物原始 Awake 由测试入口显式调用。不会把状态值验证称为连续动画、正常寻路或正常解锁关卡通过。测试会记录全部 18 个场景的异常，单项失败后继续收集本批其他结果，最后按实际结果退出。

工作流 `startup-r28-special-functions.yml` 使用现有 R28 环境准备，只运行这一个专项批次。已有静态、原生对照、完整 IL2CPP 编译和 IPA 导出不随本轮重跑。已注册入口 `bulk401-startup-runtime-gate.yml` 指向本专项；完整导出模板仍保存在 `startup-r28-diagnostic-ipa.yml`。

**当前真实 Unity 状态：入口已实现，结果待 Actions 实测。** 本地只对新增 Editor 入口做了一次实际 Unity API 编译，编译通过。
